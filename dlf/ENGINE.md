# DLF engine evidence

Evidence is scoped to the named build and observation. **Live** means observed in the game; **RE** means static inspection of the binaries; **VM** means a synthetic regression or an inherited assumption, not native verification; **Audit** means a code review without a game run. "Build not recorded" means the source document does not say. Consult [LIVE-VERIFIED.md](LIVE-VERIFIED.md) before claiming native acceptance. RVAs are for the named `client.dll`/`server.dll` build only; field offsets come from the schema tables in client.dll (a pointer to the field-name string, int32 offset at +0x10; `.scratch/dlf_stun_re/`).

## Fonts and images

| Fact | Build and evidence | Confidence boundary |
|---|---|---|
| Panorama does not load fonts from addon VPKs. The stock `fonts.conf` loads only files named on its `<fontpattern>` list, so a font must be a loose file under a listed name. A packed font and a loose `gofire.otf` were ignored; a loose `quantico.otf` rendered GOFIRE. Pango matches the family name inside the file (`ModestoLite Expanded`). | **Live 2026-10-16**, build not recorded. [ADR 0003](docs/adr/0003-fonts-as-loose-renamed-files.md). | Live for the three shipped names. A stock update that starts using `vt323`, `quantico` or `rajdhani` would change what draws. |
| The game's WebP decoder draws animated WebP as grey bars, and `ImageLoaded` still fires; GIF loads. | **Live 2026-10-16**, build not recorded; `logoSource` in `dlf_state.js`. | Live. Only Discord media-proxy and fxtwitter `.webp` URLs are rewritten to GIF; other animated WebP stays broken. |
| `text-overflow: shrink` squashed GOFIRE's stencil cuts on long names, so the banner picks a whole font size itself from the fonts' glyph advances (`FIT_ADVANCES`, `scripts/font-metrics.py`). | **Live 2026-10-16**, build not recorded. | Live for the squash. The estimated advances fit the validator's cases (VM), not every name. |
| Panorama filters textures with straight alpha: the PSD's white behind transparency drew a white outline and white specks along the torn edge when the 1920 px art was scaled. Transparent pixels therefore carry the colour of the nearest visible pixel (`export-banner-art.py` `bleed`). | **Live**, user screenshot 2026-10-20, 1600x900. | Live for the outline; the fix has not been checked on another scale. |

## Top-bar cards

| Fact | Build and evidence | Confidence boundary |
|---|---|---|
| The top bar has no account binding: no `account_id` or `steamid` dialog variable or attribute on top-bar or players-list panels. | **Live 2026-10-16**, build not recorded. | Live. |
| So the editor activates the stock PLAYERS tab, then each unknown player's `CitadelPlayersListEntry #MainContents`, and reads the opened `CitadelProfileCard`'s account through a created hidden label bound to `{i:r:account_id}` (what ShowRank Barebones does). It accepts the one card whose account changed, skips names two players share, remembers rowless names (`noAccount`) for the session and stops when the editor closes. Timing since 2026-10-24: polled every 0.03 s (card used as soon as its account reads), no gap between rows, a cardless row given up after 5x the slowest card seen (0.3-1 s); the card latency and whether the stock reuses one card panel are not measured live. The local player's card gave 215334735; bot rows open no card. | **Live**, date and build not recorded; the sequencing is checked in the VM. [ADR 0007](docs/adr/0007-player-aliases-follow-the-steam-account.md). | Live for the local player and bots; many-account behaviour is VM. |

## Billy's Chain Gang

`ability_punkgoat_tether` (installed VData 2026-10-20) has five modifiers. `pull` (`modifier_punkgoat_tether_pull`, `MODIFIER_DEBUFF_YES`, stock `m_bIsHidden true`, `PullDuration` 0.8) is the only one listed. A `cl_modifier_dump` on an Infernus bot (**Live 2026-10-20**, build not recorded) showed it as `ability_punkgoat_tether/pull` with 0.5 s left, so its panel is `status_ability_punkgoat_tether`, drawn in the enemy colour, `maxSeconds` 2. Not listed: `tether` (`modifier_punkgoat_tether`, the chained phase before the pull, `OVERHEAD_DRAW_FOR_CASTER_ONLY`, stock hidden, no seconds left in the dump), Billy's own `waiting_for_pull` (`modifier_punkgoat_tether_waiting`, visible stock), `unstoppable` and `tether_firerate_slow` (`modifier_base`, the fire-rate slow, no draw fields). The pull's client class has **not been traced**: if it also hides itself in code, the VData change shows nothing and the icon will not appear; then check STATUS LOG and consider a class swap like Bebop's. The same doubt applies to Yamato's Flying Strike target.
