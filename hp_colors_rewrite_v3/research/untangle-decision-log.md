## Rules (the constraints above, 6 lines)
1. Panorama scripts are standalone files with no module system: they share only `$`-globals. No new script, stylesheet or layout file in the pak, no change to the shipped file list or include order. Shared owners are values on an existing `$`-global (read at boot/attach, never per paint) or tools/lib modules.
2. No added per-frame or per-paint work, panel reads/writes, hot-path allocations or startup cost. New helpers write into existing objects; nothing is allocated per tick.
3. Behaviour and UI exactly the same: no control removed, no interaction changed. Where two copies disagree today the disagreement is kept and listed under Possible bugs.
4. Saved-settings format, slots, record version, codec, wire messages and every generated output stay byte-identical (`generate.js --check`, `qollock.js --check`, `showrank.js --check` green); only provably dead output is removed.
5. ENGINE.md workarounds stay (alias/explicit-stock style writes, valid() gating, relay panel, delayed re-binds, `HPV3_DEBUG` single-line markers, Closure ADVANCED name-keeping).
6. Tiers: A = dead code, one owner for a copy, tool-side tables, CLI/pin copies, pass-throughs. B = reorganise inside existing files (sections, sub-objects, one registry/helper), behaviour-preserving, verified by the existing suites named in the fix. C = not doing.
