## Recommendation and drift guard (proposed; not implemented or tested)

1. **CSS:** use the commit-pinned SteamTracking CSS as reviewed stock baseline; keep a checked-in pristine baseline (or its hash plus a reproducible fetch) and express the mod's stock-prefix edits against it. On explicit upstream refresh, fetch current CSS, check expected structural anchors, then demand an exact baseline/hash match before applying the pinned patch; a changed prefix or failed patch must stop and require review/rebase, not silently take a new prefix. Check the resulting stock sections against the selected upstream revision; compiled VPK listing is only a separate presence check.
2. **Hero keys:** generate from the same SteamTracking `heroes.vdata` at one pinned commit, selecting top-level `hero_*` objects with `_class = "CitadelHeroData_t"` via a KV3-aware parser, not a loose substring search (keys can occur in references). Compare a canonical sorted key list and any inclusion/filter flags against a checked-in snapshot; added/removed/renamed heroes fail until reviewed and the snapshot regenerated. Obtain friendly names from a verified localization mapping or maintain an explicit reviewed key→label table; never infer names from keys or silently omit prerelease heroes. The build must fail if fetched data is missing/malformed or disagrees with its pin. A pinned source alone detects **local patch/catalog drift**, not an upstream game update; detecting upstream drift additionally requires an explicit master-vs-pin check (or local installed-game version/recompiled-resource comparison), and must distinguish legitimate upstream differences from the installed game's version.
