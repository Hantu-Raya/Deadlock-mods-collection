## What the mod costs (client 6860, demo 134371706, 1920x1080 windowed; files in `.scratch/oh-untangle/live/`)

Three ways of measuring, the last two added in round 2 because the first one misled.

1. Timing every scheduled callback with `Date.now` (1 ms steps) said about 3.3 ms of script per second. That figure is
   wrong: a loop benchmark in the game (each native call 5,000-200,000 times) gave the same per-call costs the
   validator's model uses (`IsValid` 50 ns, `BHasClass` 400, a text read 250, `$.Schedule` 600, a style write
   1,000-1,800; a `FindChildTraverse` miss over `#TopBar` 86,000), and looping each step of the steady state 300 times
   gave the real cost:

   | step | before | after |
   |---|---|---|
   | host tick, once a second | 123 us (`place` 73, `ensureCards` 13, `renderNames` 13, `renderGraph` 7) | 123 us |
   | status column `render` | 30 us a call | 30 us |
   | world bar, a repeated settings message | 1.5 us a bar | 0 (skipped before the parse) |
   | world bar, idle sample | 1.5 us | 1.0 us |

   All scripts together are about 0.25 ms per second, which is 0.002 ms of a frame at 120 fps. The validator's
   model (218 us a second) was right all along.
2. Drawing: our panels faded out and in every 4-10 s while PresentMon timed every frame. Playing, the scene noise
   swamps it (one run said +0.73 ms, the next -0.51 ms, the no-op control +0.17, each +/-0.26). With the demo paused
   (a still scene) all our panels together cost 0.04 +/- 0.04 ms a frame; no part stands out.
3. The whole mod against no pak10, paused on the same tick (94050), 60 s each: 4.22 and 4.20 ms without, 4.03 and
   4.20 ms with.

So the mod has no cost that shows in the frame rate, and there is nothing to win there. What round 1 saved is the
settings parse per world bar (row 3). `place()` is the host's change detector (it reads the geometry it compares), so
it stays.

## Engine facts from panorama.dll 6860 (`re/panorama-findings.md`, read from disassembly, nothing run)

- A same-value `style.X`, class or plain label text write returns before any restyle, but still pays the call, a CSS
  parse and an allocation: the JS write cache stays worth it.
- `$.Schedule` is one global queue sorted by fire time; waiting entries cost nothing per frame; delays round to frames.
- `Children()` allocates an array per call; `FindChildTraverse` has no id index; `GetChildCount`/`GetChild`/`GetParent`
  read a field; `actuallayoutwidth` forces no layout.
- Class names are interned for good: never build unbounded class names at run time.
- A running CSS animation repaints its panel every frame; this mod has three infinite ones, all on panels that show
  briefly (`.OHBuyBg`) or on the post-game board.

## D. Larger redesigns considered and left (reason)

- One `FIELDS` table driving normalize, link `set`, editor render/bind/reset (F1): changes what a too-long edit does
  and touches every editor check; a feature-sized change, not provable identical.
- Save transport out of the editor into the host, shared with the board (F3): the board runs in another context
  (dashboard), so "shared" means a third included script; moves the 0.3.1 store code that has live evidence.
- Shared panel helper script for share box, logo loader, hero picker (F5): the copies differ on purpose in places
  (lobby empties the box after copy, live finding); merging changes behaviour.
- Splitting `oh_host.js` (2447 lines) into files: Closure output contracts and include order per file; no behaviour gain.
